## REST API

### Register a user

```
POST /auth/register
```

Request Example

```
{
    "title":"Register User",
    "username:"exaple",
    "email":"exampleexample",
    "password":"Password123"
}
```

Response Example

```
{

  "title": "Register Succeed",
  "status": 200,
  "detail": "User Registered Successfully",
  "instance: "/auth/register"

}
```

Error Example

```
{

  "title": "Register Failed",
  "status": 422,
  "detail": "One or more fields failed validation checks.",
  "instance: "/auth/register",
  "errors": [
    {
        "field": "email",
        "message": "The format is missing an '@' symbol."
    }
  ]

}
```

## Error Format

The API error format follows the Standard RFC 9457 Format

- title: A short, high-level summary of the problem that does not change across occurrences of the same issue.
- status: The HTTP status code generated by the origin server for this occurrence of the problem.
- detail: A human-readable explanation specific to this error occurrence, serving as debugging context for developers.
- instance: A URI reference that identifies the specific resource or endpoint where the error occurred.
- errors (Extension): A custom array used to bundle multiple input validation errors together in a single response, identifying exactly which parameters failed verification

### Error Format Example

```
{
  "title": "Validation Failed",
  "status": 422,
  "detail": "One or more fields failed validation checks.",
  "instance: ""/v1/users/signup"",
  "errors": [
    {
        "field": "email",
        "message": "The format is missing an '@' symbol."
    }
  ]
}
```
